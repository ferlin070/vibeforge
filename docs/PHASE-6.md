# RC2 Phase 6 — cloud and recovery

Shared strict project and snapshot validation, bounded JSON shape, dangerous property rejection at every level, draft document preservation, review and dependency consistency. Invalid local records trigger write protection; valid records remain available. Emergency export preserves original bytes and requires explicit confirmation because it may contain secrets. Only explicit recovery confirmation replaces the old local storage. Invalid cloud snapshots are excluded, not deleted. Cloud restore validates row identity and nested project fields. Cloud save validates the original and redacted copy.

Session access and refresh tokens remain in React memory, refresh before expiry, and clear on failure/expiry. Recovery and resend use Supabase Auth REST; recovery callback removes tokens from the fragment and updates the password after explicit form submission. No account is created, email sent, database changed or deployment performed by this audit. Real SMTP, allowed redirect URL, live account recovery and browser tests remain required. Older malformed records are retained in raw recovery backup, not silently repaired. Strict limits may require manual correction of legacy data.
