# RC7 — Local runner pilot

OpenCode task packages now optionally include runner.mjs. The runner defaults to check-only; --launch requires an interactive terminal and explicit LAUNCH confirmation, repeats the Git preflight, then starts the installed OpenCode executable with inherited terminal streams and no shell. The operator reviews permissions and the task, and pastes the prompt manually. See https://opencode.ai/docs/cli and https://opencode.ai/docs/permissions/. Review installed-version documentation before use. The runner cannot enforce agent permissions, does not sandbox the process and does not support shell wrappers. Use an isolated trusted checkout. Agent access to local files, networks and paid models remains the operator's responsibility.

On normal process exit, an unsigned RECEIPT.json is created exclusively outside the worktree (existing receipts are not overwritten). It contains only task/target metadata, exit status and finish time, not logs or credentials. Mission Control checks the receipt against the current approved OpenCode assignment and pinned repository and appends a summary to a report draft only after a recorded handoff. It does not automatically submit, approve, verify, execute or deploy anything. Exit code zero is not proof of successful implementation or tests.

Other agents retain manual handoff packages. This pilot is not live remote orchestration, device pairing, real-time telemetry or a network service. CI uses a disposable Git repository for preflight and noninteractive launch rejection and tests receipt validation. Actual OpenCode execution and Windows compatibility need operator UAT.

## Conservative Git preflight

The beta preflight rejects inherited Git environment overrides (except the two explicitly reset prompt/locking variables), configured Git filters, submodules and assume-unchanged or skip-worktree index flags. These can otherwise change what Git inspects, execute external helpers or conceal working-tree changes. For affected repositories, inspect the checkout manually rather than disabling project settings or discarding work. This is a conservative check for a trusted Git installation and checkout, not a sandbox or comprehensive integrity proof. The automated fixtures exercise the new rejection paths.
