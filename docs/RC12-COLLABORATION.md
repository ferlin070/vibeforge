# RC12 — Shared draft collaboration pilot

Billing is deferred at the operator's request. The pilot supports direct sharing between registered account IDs. The sender explicitly previews and confirms a brief containing only name, type, idea, audience and agent; recognized secrets are redacted client-side. Recipients may import a separate local draft with a new ID and no approval, repository, evidence, memory or task assignments. There is no directory lookup, email invitation, live editing or shared organization workspace. Share IDs are not authentication credentials; access is determined by the signed-in identity and RLS.

An additive migration named rc12_shared_drafts is applied to the existing VibeForge Supabase project; its source is docs/sql/rc12_shared_drafts.sql. RLS allows sender and recipient to read; only sender can insert and delete, no authenticated update grant, no anon grants. Foreign keys reference auth users. A synthetic three-identity PostgreSQL test passed read, third-party exclusion, spoofed sender rejection, recipient mutation rejection, sender revocation and rollback. No customer rows were changed. Test rows were rolled back and their absence verified. This is SQL authorization testing, not a live end-to-end Auth/PostgREST test.

Revocation stops subsequent access to the shared row; it cannot recall copies already imported or downloaded. Treat account IDs as private contact information and confirm recipient identity independently. The current list is capped at 50 recent visible shares. Redaction is best effort, not a guarantee of privacy. Team collaboration remains a pilot pending browser UAT with two real accounts, direct API abuse/quota controls, privacy review and group membership/role design. The personal workspace schema is unchanged.
